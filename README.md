## 一、这个作品是什么

一个把「我做过的项目」做成星球的个人作品集网站。核心不是静态展示，而是一套**可交互的空间叙事**：

| 体验 | 说明 |
|---|---|
| 拓扑线框星球 | 170 个球面光点 + k 近邻三角网格连线，青绿色微光，缓慢自转（灵感来自 Topology Field 组件） |
| 花朵形项目分区 | 球面被划分成若干朵花瓣形状的区域，每朵花代表一个项目，各有独立色相与瓣数 |
| 悬停地图式放大 | 悬停一朵花 → 画面像放大地图一样推近，整朵花霓虹高亮，同时拉出虚线接一段项目介绍 |
| 锚点创建项目 | 在两朵花之间的空隙光点上点击，即可在该位置种一朵新花（自定义花瓣、色相、时间） |
| 时间线航线回放 | 像航班轨迹视频那样，沿紫色大圆弧从早期项目飞到后期项目，途经花朵逐朵点亮 |
| 点击进 PPT | 点击已上线的花朵，淡出转场进入该项目的演示页 |
| 速度滑杆 | 左下角可拖动的速度条（0.5 一小格 / 整数一大格），实时调节自转快慢直到完全停转 |
| 访客 · 站长双模式 | 访客无密码自由浏览、编辑入口全关；站长密码解锁后可增删项目、导出/导入项目数据 |

## 二、技术实现要点（值得单独说的几处）

整个控件画在一块 `<canvas>` 上，无框架、无依赖，双击 `index.html` 即可运行。

**1. 球面 → 屏幕投影**
黄金角（golden angle）均布 170 个球面点，`projectPoint()` 做绕 Y / X 轴旋转 + 透视投影，附带深度值用于近大远小与背面剔除。

**2. 光标处缩放（整个交互手感的关键）**
早期版本「悬停在光点上但画面还是在抖」，根因是放大锚点取了目标中心 —— 目标会滑离光标，于是悬停丢失、镜头缩回，循环成卡顿。修正为真正的定点缩放：

```
a_target = a + (S − cam) · (1/z − 1/zt)      // S=光标, z=当前倍率, zt=目标倍率
```

按目标倍率反推锚点，使光标下的世界点在缩放前后**屏幕坐标保持不变**。数值验证：60 帧插值期间该点最大漂移 0.31px，而丢失悬停需要移出 30px，因此状态在机制上不可能抖动。

**3. 悬停防抖三件套**
回滞判定（进入 15px / 释放 30px）+ 粘滞保持 + 悬停时转速缓动归零。三者叠加才彻底消除了「想知道停没停却总是飘」的问题。

**4. 航线的大圆弧插值**
`arcPoint()` 用球面线性插值（slerp）生成两点间最短路径，再叠加 `sin(πt)` 的离地抬升，形成航班线那种「起飞拱起、降落回落」的弧线；配紫色发光底线 + 彗尾拖尾 + 按航向旋转的纸飞机机头。

**5. 可读可维护的版本分工**
本地 `yworld-site/` 是可编辑版（含站长模式），运行 `node build-readonly.js` 自动产出不含任何编辑入口的 `yworld-site-public/`，再发布为 HTTPS 只读站点。源码里所有站长相关 UI 都在构建时被剥离，而不是靠前端标志假装存在。

## 四、本地运行与发布

```bash
# 本地编辑（双击即可，或起个静态服务）
start yworld-site/index.html

# 生成只读发布镜像
node build-readonly.js            # → yworld-site-public/

# 项目数据随身携带（站长模式下操作）
#   右上角 🔓 站长模式 → 💾 导出项目数据 → yworld-projects.json
#   换电脑后：先把 JSON 放回 yworld-site/，解锁后 📥 导入，再运行 build-readonly.js 即可烘焙进只读版
```

站长默认密码是 `yworld`。想修改：在 `index.html` 里搜 `PASS_HASH`，注释中有换算新密码哈希的一行命令。

## 五、关于 AI Coding

这个项目的每一次改动都源于一句自然语言描述的需求，再由 AI 完成设计判断、数学推导、代码实现与回归验证。完整的逐轮记录见 **[CHANGELOG.md](./CHANGELOG.md)**，其中包含：你提出指令的时间、当时的目标、具体改了什么代码、以及最终呈现的效果 —— 共 14 轮迭代，横跨约 12 小时。

> 有些问题不是一次解决到位的：光点悬停抖动这件事来回修了四轮才找到根因（把「感受补偿」变成「数学上不可能」）。这段过程原样保留在 CHANGELOG 里，比一个光滑的结果更有参考价值。
